- (decision) Spec covers both the TaskFlow product (Kanban task manager) and the 5-wave agent-dispatch delivery process as one contract, since practicing that process is the stated Project Goal in CLAUDE.md, not just building the app
- (capability) CAP-1 Register: user creates account (email/password/name) and receives a JWT; success: POST /api/auth/register returns {data:{token,...}} for a new unique email, {error} for a duplicate
- (capability) CAP-2 Login: user authenticates with email/password and receives a JWT; success: POST /api/auth/login returns a token for valid credentials, {error} otherwise
- (capability) CAP-3 Create task: authenticated user creates a task with title (required) and description (optional); success: POST /api/tasks persists a task scoped to that user, visible in a subsequent GET /api/tasks
- (capability) CAP-4 View board: user sees their tasks grouped into To Do / In Progress / Done columns, ordered by position; success: GET /api/tasks returns status+order fields the client renders into three columns
- (capability) CAP-5 Move task: user drags a task to a new column/position and it persists; success: PATCH /api/tasks/:id/move updates status/order and the change survives a page reload
- (capability) CAP-6 Edit task: user updates a task's title/description; success: PATCH /api/tasks/:id persists the edit
- (capability) CAP-7 Delete task: user removes a task; success: DELETE /api/tasks/:id removes it from subsequent GET /api/tasks
- (capability) CAP-8 Parallel agent-team delivery: each story is implemented by dispatching role-scoped subagents (Scrum Master, DB Engineer, Backend Dev, Frontend Dev, Integrator) across 5 sequential waves with no overlapping file writes; success: one full story is delivered through all 5 waves, each wave passing bmad-code-review and landing its own PR before the next wave dispatches
- (constraint) Auth is JWT-only, 7-day token expiry, no OAuth/SSO or third-party identity providers
- (constraint) Passwords hashed with bcrypt, minimum 10 salt rounds; plaintext or weaker hashing is rejected
- (constraint) Every API response follows the {data: T} success / {error: string} failure envelope; no ad hoc response shapes
- (constraint) CORS restricted to http://localhost:5173; no other origins without an explicit change
- (constraint) TypeScript strict mode, named exports only, functional React components only; no class components or default exports
- (constraint) Each of the 5 roles (Scrum Master, DB Engineer, Backend Dev, Frontend Dev, Integrator) may only write inside its own owned directory per CLAUDE.md's ownership table; this is what makes parallel dispatch safe from merge conflicts
- (constraint) Every wave is gated by bmad-code-review before its PR opens, and the next wave cannot dispatch until that PR lands; no wave skips review
- (constraint) Same-directory parallel dispatches (e.g. two Frontend stories in one wave) must consume shared architecture-spine seams (shared hook, response-envelope helper, token handoff convention, canonical DTO, shared test harness) rather than inventing their own, per epics-to-agents-handoff.md
- (assumption) Non-goals inferred from what CLAUDE.md's schema/endpoints omit: no real-time/multi-user collaboration, no team or shared boards (schema has no team concept), no OAuth/SSO/password-reset/email-verification flows, no mobile app or offline support, no user-defined columns (status fixed to todo/in_progress/done), no CI/CD or production deployment pipeline (Running the Project section only covers local dev)
